Method, prices and comparison with the handbook-only estimate

The 10,069-token handbook estimate used tiktoken/o200k_base as a proxy, not a verified gpt-6-luna tokenizer. It predicted a 90% reduction for handbook input alone. Real agent savings are 86.8% because calls also include tools, prompts, document text, outputs and cache writes. The shared cache prefix includes more than just the handbook. Earlier calls could already have warmed the cache.

Supplied prices per million tokens: ordinary input $0.10; cached input $0.01; cache writes $0.125; output $0.50. Cost = [(input − cached − writes) × .10 + cached × .01 + writes × .125 + output × .50] ÷ 1,000,000. Token charges are calculated from API reports; provider invoices, gateway fees and infrastructure were not verified.

03

Three layers, with measured net overhead.

Protect document input, purchasing authority and model behavior independently.

Code / visibility

Clean before model input.

Remove hidden or invisible HTML/PDF text and normalize formatting controls. The P7 upgrade adds offline browser layout, PDF paint-order checks and primary-label evidence. Genuine ambiguity becomes a human-review flag.

Design / authority

Separate extraction from action.

The model extracts facts. Trusted handbook code computes the decision from source anchors. Trap schemas are withheld during defended review, and exact, one-use human authorization is enforced in the functions.

Prompt / trust boundary

Documents supply facts.

Explicitly treat vendor content and tool returns as untrusted data. Reject role spoofing, forged authorization and instructions to change handbook rules, while preserving legitimate quote corrections.

06

Deploy a review workflow, not an autonomous buyer.

The economics are promising. The evidence supports a supervised pilot, with limits made visible.

Real mail needs a human decision gate.

Practice performance improved, but one new CSS price mask still produced an incorrect rejection and two exam records lacked usable primary fields. Ten keyless exam outputs cannot establish production accuracy.

  • Have a buyer compare each recommendation with the normally rendered quote. Route unknown fields, conflicting labels and rendering discrepancies to review.
  • Keep email and payment tools simulated. Any future real action needs explicit, exact human authorization and a separately reviewed integration.
  • Resolve CSS-generated content/occlusion gaps and test a broader held-out mix before unattended intake. Scanned PDFs, multi-item quotes, remote styling and supplier impersonation remain outside reliable coverage.
  • Preserve full defenses, actual usage and audit logging. A familiar vendor name or visible quote cannot authenticate a supplier.

The normal CLI default remains undefended for historical testing. Operational reviews must explicitly select all upgraded defenses; the exam harness did so.
